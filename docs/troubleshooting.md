# Troubleshooting the local demonstration

Run commands from the repository root. `docker compose ps` should show four healthy services; `scripts/smoke.sh` checks actual database readiness plus HTTP 200 for mock billing, support API, and web within a single 120-second budget. Inspect `docker compose logs --tail=100 <service>` for a failing service. Avoid sharing `.env`, database URLs, or fully expanded Compose configuration.

## Every POST returns 403 `origin_not_allowed`

The API requires an exact browser `Origin` for state changes. `ALLOWED_ORIGINS` is comma-separated, with scheme, host and port, no wildcards or trailing slash. Local browser: `http://localhost:5173`. Codespaces browser: `https://${CODESPACE_NAME}-5173.${GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN}` (normally `app.github.dev`). Use the URL from the Ports panel, not a forwarded support API URL.

A moved Codespace, another forwarded port, or localhost Playwright against a Codespaces-only `.env` can cause this error. Add the intended exact origin and recreate the support API; environment changes require container recreation. The README's Python override adds localhost for browser QA without changing or printing secrets. The Vite proxy changes `Host` only and preserves the browser's `Origin`. Do not disable origin checks.

## Vite says the host is not allowed (`allowedHosts`)

Compose supplies `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN` to web; Vite permits localhost and that forwarding-domain suffix. Confirm the actual forwarded hostname belongs to that domain. If the domain is absent or different in the Codespace shell, set it to the actual domain and recreate/rebuild web. Keep `server.allowedHosts` scoped to the intended domain; do not set it to `true`.

## Secure cookie on `http://localhost`

`uas_session` is HttpOnly, Secure, SameSite=Lax, and scoped to `/api`. Chromium and Firefox allow Secure cookies on `http://localhost`, so the local demo works at the documented hostname. Use exactly `localhost`, or HTTPS for a non-localhost host; arbitrary HTTP hostnames and `127.0.0.1` are not interchangeable with the documented origin. The automated browser suite exercises Chromium; Firefox was not separately tested for this milestone.

If conversations disappear or return 404, inspect the browser's cookie storage for the web origin and use the same origin for every request. An old conversation ID in localStorage with an expired/cleared cookie belongs to another session: start a new conversation. Ownership failures intentionally look identical to missing conversations. A cookie is never available to browser JavaScript.

## Database or startup problems

`init-env.sh` refusing an existing `.env` is intentional. Retain it when restarting. Generating different passwords while keeping an existing database volume will not reset database roles. Do not delete volumes or regenerate secrets to address routine readiness errors. Check container health, port conflicts on 5432/8000/8001/5173, and the failing service's startup logs. Database initialization scripts run once on empty storage; service migrations run on service startup.

A failed smoke command returns nonzero if the database is missing/unhealthy even when API liveness responds. `SMOKE_TIMEOUT_SECONDS` can lower the smoke budget for diagnostics (integer 1–120); it cannot raise the 120-second cap. A build that is still downloading dependencies must finish before starting smoke.

## Authentication or upstream errors

Three wrong knowledge checks within 15 minutes lock the conversation and normalized identifier for 15 minutes across browser sessions. Punctuation or a new cookie does not bypass the lock. Lockout, incorrect answers, and occupied verification slots deliberately show the same message. Wait for expiry or use another synthetic persona.

Timeouts and billing 5xx are recoverable and never count as wrong knowledge checks. Inspect only metadata in the English debug drawer. Clear authenticated `/_dev/faults` rules or restart mock billing, then submit again. These endpoints exist only when fault injection is enabled; missing/wrong admin credentials produce 401. The service API key is insufficient for fault administration.

## Tests cannot reach Postgres or the browser

Start Compose first. Use the host test URLs generated by `init-env.sh`, Python 3.12, and `.venv/bin/pytest --asyncio-mode=auto --tb=short` for a root combined run. Do not run separate schema-rebuilding test processes concurrently. Install Chromium and its libraries using the README commands. Browser QA in Codespaces also requires the additive localhost origin override documented there.
